# Goal protocol sources

The existing Codex native contract remains verified by `crates/aionui-session/src/backend/codex_goal.schema.json` and its native captures (Codex CLI 0.161.0).

Additional first-party contracts inspected for this integration:

- Claude ACP: agentclientprotocol/claude-agent-acp commit `a79d07324dc15808c94a889a3b60615cca5a9fbd`, `src/goal-extension.ts` blob `5c3077a83108b9a9738bff5a298f9dfc55eb1b01`, and `src/acp-agent.ts` blob `a96add946a5297c6133710d64aaf07d3605c5afa`. The controls are set/clear, and `active_goal.value` is structured state. Clearing is not evidence of completion.
- ACP Goal: upstream Codex and Claude `docs/air-extensions.md`, Goal sections. `_session/goal` and its action subset are advertised in initialize `_meta.jetbrains.air.goal`; historical versions used `_meta.goal`. The client retains its own identity and opts into the documented metadata namespace. Unsupported actions are rejected before transmission.
- Qwen: QwenLM/qwen-code commit `07a4fda66622fc5337f4182d956736af146dad87`. `packages/acp-bridge/src/status.ts` blob `0445eea7f70afa60c387a796f80d3386f8ecf82d` defines `qwen/control/session/goal/get` and `.../control`; `packages/core/src/goals/goal-protocol.ts` blob `129ff4da89801900263036ae6cf74ba7918c807a` defines v2 state and identity/revision guards. `packages/cli/src/acp-integration/acpAgent.ts` blob `76e9bd5e7965d7bfd10e64dae39f59fc23df0a49` handles those controls. `_meta.goalState` is decoded separately, not mistaken for the neutral extension.

Native Claude capture: `crates/aionui-session/src/backend/claude_goal.capture.ndjson`, recorded with CLI 2.1.267 in an isolated config/cwd with dummy credentials and a non-listening local API address. `CLAUDE_CODE_REMOTE=1` enables the native structured `active_goal` stream; the same probe without that setting produced no Goal state. The capture contains initial empty state, an explicit set with authoritative state, and a clear tombstone. No remote model or user task was used. This verifies state/control transport; it does not prove successful long-running model work.

Missing metrics remain absent. ACP millisecond timestamps are converted to the existing Core API seconds; plugin contracts continue to use milliseconds. No host continuation loop is added. Kiro is outside this change.

The generic Goal v1 extension negotiates controls and authoritative state, not a universal foreground-turn lifecycle. In particular, the inspected Claude ACP implementation reports autonomous foreground boundaries through its v2 foreground interface, not through Goal v1 itself. The hermetic neutral/AIR fixture verifies negotiation, action gating and session isolation only; it is not proof that an arbitrary ACP agent's autonomous work has complete lifecycle support. Native Claude and Qwen have separate live transport/persistence probes. The existing bounded orphan-stream relay can retain unsolicited output, but Goal state or an RPC acknowledgement is never synthesized into a turn-finished signal.

Qwen live capture: `crates/aionui-session/src/backend/qwen_goal.capture.ndjson`, official npm `@qwen-code/qwen-code@0.26.7`, integrity `sha512-sRFWwmakpvF3bWBfG1M/ijoZG5h8Yxs0IC4cXZP3dJLyEbbTHItyhzMySG4o4CzLGFIfofArummQJo/xcggweQ==`. Run in an isolated QWEN_HOME/cwd with dummy OpenAI credentials and a non-listening local API address. Verified initialize, new session, read, create, pause, resume, clear, state events and native activity. Real wire uses `qwen/control/session/goal/get` and `.../control` WITHOUT a leading underscore. Clear retains the last goal ID/revision/timestamp, so a same-version clear tombstone must reject delayed active snapshots with the same identity. No remote model or user task was used.
